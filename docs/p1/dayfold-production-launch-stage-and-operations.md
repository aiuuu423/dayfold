# Dayfold 正式公网上线阶段与操作

状态：阶段已判定，正式上线未批准  
日期：2026-09-22  
当前阶段：P1 Closeout / P2 Entry Gate  
目标形态：中国大陆备案的响应式 Web MVP

## 当前判定

Dayfold 目前不是“准备切 DNS 上线”的阶段，而是：

```text
P1 技术可行性验证基本完成
        ↓
P1 收口与 P2 进入门槛
        ↓
P2 Technical Specification
```

已经证明：

- Vercel + Render Preview 公网链路、HTTPS、CORS 和中国多运营商基本可达。
- CloudBase 上海 PostgreSQL、pgvector、Auth 用户名登录和 FastAPI 云托管技术路径可运行。
- Memory Extraction 的模型、Prompt、数据集和评测基线已建立。
- 正式生产地域冻结为中国大陆华东（上海）。

尚未完成：

- 正式产品功能没有按 MVP 规格实现。
- 正式数据库 Schema、迁移和备份恢复没有设计或验证。
- CloudBase Auth 没有完成服务端 Token 校验、邮箱流程、账户删除和生产承诺。
- 正式备案资源、根域名或 `www` 入口没有冻结。
- ICP 备案、公安联网备案和 AI 服务合规判断没有完成。
- 真实用户跨账户隔离、删除传播、安全与灾备测试没有完成。

因此现在可以开始 P2 技术规格，不得直接开放真实用户注册，也不得把 CloudBase 免费环境升级为生产环境。

## 阶段模型

| 阶段 | 目标 | 当前状态 | 进入下一阶段的门槛 |
|---|---|---|---|
| P1 Feasibility | 验证模型、Memory、网络、CloudBase 基础能力 | 基本完成 | pgvector 人工确认与 P1 记录收口 |
| P2 Technical Specification | 冻结正式系统边界、Schema、Auth、删除、备份与部署规格 | 下一阶段 | 规格通过人工评审，生产资源成本与备案路径明确 |
| P3 MVP Implementation | 实现账户、Today、Chat、Memory、Growth 与设置的最小纵切 | 未开始 | 自动化测试与无真实数据 Staging 通过 |
| P4 Production Readiness | 完成备案、安全、隐私、AI 合规、灾备和小流量验证 | 未开始 | 所有发布阻断项关闭 |
| P5 Public Beta | 对有限真实用户开放并监控 | 未开始 | 稳定性、删除、投诉与事故响应达标 |
| P6 General Availability | 正式公网发布与持续运营 | 未开始 | 公测结论通过并具备长期成本与运维能力 |

## P1 收口

P1 剩余工作只处理验证结论，不继续扩展功能：

1. 获得 CloudBase 人工工程师对 pgvector 的明确回复。
2. 把 CloudBase Auth、PostgreSQL、FastAPI 和费用证据写入正式记录。
3. 删除或归档全部虚构测试用户、临时表和不再需要的验证资源。
4. 冻结 P2 输入：CloudBase 是首选候选，不是已批准生产方案。
5. 保留 Vercel + Render 作为无真实数据 Preview，不与正式环境共享 Secret。

P1 完成标准：

```text
技术证据可复核
未决项有明确负责人和阻断级别
没有真实用户数据
没有隐藏的按量付费
没有把 Preview 描述为 Production
```

## P2 技术规格

P2 需要冻结生产系统的事实来源和失败边界，不直接购买资源或开发完整界面。

### 身份与账户

需要定义：

- CloudBase Auth 的正式登录方式、回调域名和 Token 校验路径。
- React 前端不得保存 Client Secret。
- FastAPI 验证 Issuer、Audience、签名、有效期和角色。
- Provider `sub` 映射到 Dayfold 内部 `user_id`。
- 所有业务查询强制包含内部 `user_id`。
- 用户禁用、Session 撤销、密码找回、数据导出和账户删除。
- 身份删除失败时的幂等重试与业务数据冻结。

CloudBase Auth 生产采用前必须完成邮箱或其他可恢复登录方式。只支持测试用户名密码不足以开放真实用户。

### 数据与 Memory

需要定义：

- PostgreSQL Schema 与迁移工具。
- Journal、Chat、Memory、Embedding、Growth 和删除任务的数据模型。
- pgvector 维度、距离类型、HNSW/IVFFlat 选择和索引重建策略。
- 原始内容先保存、AI 任务后执行的事务边界。
- 删除原始内容后派生 Memory、向量和回顾的失效顺序。
- 数据库不开放公网写入，API 与 Worker 使用私有网络。
- 备份频率、保留期、加密、恢复点目标和恢复时间目标。

### 部署与环境

正式环境至少区分：

```text
Preview    虚构数据，Vercel + Render 或 CloudBase Probe
Staging    无真实私人数据，生产等价配置
Production 真实用户数据，中国大陆华东（上海）
```

每个环境使用独立：

- PostgreSQL 数据库。
- Auth 应用和回调域名。
- API、Worker 和前端部署。
- Secret、日志、备份和告警。

生产 CORS 只允许冻结后的正式前端 Origin，不复用 Preview 域名。

## P3 MVP 实现

实现顺序保持最小纵切：

1. 账户、登录、内部用户映射和跨用户隔离。
2. Today 文本记录的创建、查看、编辑和删除。
3. Chat 多轮对话、流式回复、停止和失败重试。
4. Event、Interest、Goal 三类 Memory 的提取、存储和状态。
5. Embedding、向量检索、来源过滤和上下文组装。
6. Memory 来源、修改、删除和总开关。
7. 基础 Growth、Me、设置与账户注销。
8. 隐私政策、用户协议和 AI 服务说明页面。

以下能力不进入首版：

- 完整 Timeline。
- 复杂 Themes。
- 主动陪伴和通知。
- 图片、语音、视频与地点记录。
- 社区、积分和订阅体系。

## P4 生产准备

### 备案资源

腾讯云要求中国大陆网站在开通前完成 ICP 备案：

- https://cloud.tencent.com/document/product/243/37402

当前免费 CloudBase 环境不能直接作为正式备案资源。腾讯云备案文档说明：

- CloudBase 备案资源剩余有效期须大于 6 个月。
- CloudBase 需要开启固定公网 IP。
- 每个 CloudBase 资源支持备案 2 个网站或 APP。
- 云托管资源包自 2021-08-05 起不再支持新增域名备案。
- CVM 或轻量服务器可用于备案，但必须位于中国境内、有公网 IP、包年包月购买至少 3 个月，备案期间剩余有效期不少于 1 个月。

来源：

- https://cloud.tencent.com/document/product/243/18908

正式资源选择必须在以下两条路径中冻结一条：

```text
路径 A：符合备案条件的 CloudBase 付费资源 + 固定公网 IP
路径 B：符合备案条件的上海 CVM / Lighthouse，承载正式入口或作为确认可用的备案接入资源
```

在购买前向腾讯云人工确认：

- CloudBase 付费环境能否为 Dayfold Web 正式域名完成新增备案。
- HTTP 网关、自定义域名和固定公网 IP 的组合方式。
- CloudBaseRun、PostgreSQL 和 Auth 是否能保持上海同地域。
- 续费价格、资源点消耗、停服和数据导出规则。

### ICP 备案

操作顺序：

1. 冻结备案主体为个人或单位。
2. 确认腾讯云账号实名主体与备案主体一致。
3. 确认 `dayfold.com.cn` 域名实名信息一致。
4. 购买符合条件的备案资源。
5. 准备网站名称、服务内容、负责人、证件和域名材料。
6. 在腾讯云备案系统提交首次备案。
7. 完成腾讯云初审、短信核验和管局审核。
8. 获得备案号后，在正式页面底部展示备案号和链接。

备案通过前，根域名和 `www` 不指向可注册的正式产品。

### 公安联网备案

网站获得 ICP 备案号并开通后，应在 30 日内完成公安联网备案：

- https://cloud.tencent.com/document/product/379/14655

公安备案通过后，将公安备案号、图标和链接放入网站底部。

### AI 服务合规

Dayfold 向公众提供 AI 对话、记忆提取和成长回顾，公开前需要完成专项判断：

- AI 输出的显式标识和可导出内容标识。
- 是否需要生成式人工智能服务备案或登记。
- 是否属于具有舆论属性或社会动员能力的互联网信息服务。
- 是否需要安全评估、算法备案或新技术新应用评估。
- 上游模型是否已备案，Dayfold 作为应用层服务还需承担哪些义务。
- 内容安全、投诉举报、未成年人和高风险表达处理。

国家网信办 2026 年执法案例已经包含“通过 API 中转调用多个大模型并提供对话问答，但未按规定开展安全评估”的网站，也包含未落实 AI 生成内容显式与隐式标识而被责令下线的小程序：

- https://www.cac.gov.cn/2026-09/15/c_1790876152357946.htm

因此不能只依赖上游模型已备案来推断 Dayfold 自动合规。正式公测前应取得具备中国互联网与生成式 AI 经验的合规意见，并保存判断依据。

### 隐私与安全

公开真实用户前必须通过：

- 隐私政策、用户协议、AI 服务说明和第三方处理者清单。
- 最小必要收集、目的限制和单独同意场景判断。
- 日志脱敏，禁止记录完整日记、聊天、Token 和 API Key。
- 用户 A 无法读取、修改、删除或召回用户 B 的数据。
- 删除或关闭的 Memory 不再进入模型上下文。
- 账户注销删除原始内容、派生内容、向量和后台任务。
- 数据库备份恢复实际演练。
- Secret 轮换、依赖漏洞扫描、限流和防暴力破解。
- 监控、告警、事故响应和用户通知流程。

## P5 公测

公测不直接开放无限注册。首轮只接纳有限用户，并具备：

- 邀请或容量控制。
- 明确的测试性质和数据风险说明。
- 每日错误、延迟、模型失败和异步积压监控。
- Memory 错误召回、删除失效和跨用户隔离监控。
- 用户反馈、投诉、数据导出和注销入口。
- 可立即关闭注册、AI 调用或 Memory 写入的开关。

任何跨用户数据泄漏、删除失效、备份不可恢复或身份绕过都属于停止公测的阻断问题。

## P6 正式上线

正式上线当天的操作顺序：

1. 冻结生产版本和数据库迁移。
2. 完成生产备份并验证恢复点。
3. 确认 Auth 回调、CORS、Cookie 和 HTTPS 只指向正式域名。
4. 确认隐私政策、协议、AI 标识、ICP 与公安备案展示。
5. 先将正式域名 DNS TTL 调低并记录原值。
6. 以小比例或受控账号验证注册、记录、对话、Memory、删除和注销。
7. 逐步开放流量，不直接删除 Preview DNS。
8. 观察错误率、延迟、数据库连接、任务队列和模型失败。
9. 达到阻断阈值时回滚 DNS 或停止注册，并保留数据库写入一致性。
10. 发布后 24 小时和 7 天分别复核稳定性、成本、投诉与删除任务。

正式上线不是把 Preview 域名改名。Production 必须拥有独立资源、数据、Secret、Auth、备份、日志和回滚路径。

## 当前下一步

当前唯一正确顺序：

```text
CloudBase pgvector 人工工单
        ↓
P1 验证记录收口
        ↓
P2 Technical Specification
        ↓
生产资源与备案路径报价/确认
        ↓
MVP 实现与无真实数据 Staging
        ↓
合规、安全、恢复与隔离验证
        ↓
ICP 备案
        ↓
受控公测
        ↓
正式公网
```

此时不应执行：

- 向免费 CloudBase 环境写入真实私人数据。
- 直接把 `dayfold.com.cn` 根域名绑定到 Probe。
- 创建正式用户表或 Memory Schema。
- 开放真实用户注册。
- 购买未经过 P2 规格和长期价格确认的资源。
- 把默认 CloudBase 域名当作正式入口。
